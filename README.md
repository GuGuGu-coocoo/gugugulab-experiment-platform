# GEP — GuguguLab Experiment Platform

GEP 是一个正在开发的自托管心理实验平台，计划提供实验发布、参与管理、可靠数据采集和授权导出。实验在参与者的浏览器或电脑上运行，GEP 负责服务端管理与数据接收。

**当前状态：设计与开发准备阶段。仓库尚无可运行实现、安装步骤或功能验收结果，不可用于真实研究收数。**

## GEP 与 GEC

- **GEP**：研究者图形后台、研究和版本管理、参与准入、数据接收与导出。
- **GEC**：随实验集成的客户端插件，通过薄适配层接入实验自己的数据模块，负责本地保存、上传和恢复。

实验本体保留刺激呈现、随机化、输入、计时和评分逻辑，不依赖 GEC 专用接口。开发者可以先使用本地数据后端，再切换到 GEC 后端接入平台。

## 首版开发目标

以下均为计划能力，尚未实现或验证：

- Godot Web 实验托管，以及一个经实际验证的桌面系统上的独立原生实验发行。
- 研究者后台登记研究、上传网页实验、管理发布，并为独立程序导出连接配置。
- 三种参与方式：无需 ID、研究人员发放 ID、研究人员发放 ID 与密码。
- 网页与原生客户端先本地保存、后台分批上传，服务端持久化后确认并去重。
- 按实验声明的检查点进行受控恢复；区分任务结束与数据全部收齐。
- 研究范围内的权限控制、固定快照 JSONL 与有限 CSV 导出。
- 最小 Docker Compose 部署及合成数据故障验证。

当前不开发通用 Runner。其他实验工具适配、跨设备无缝恢复和正式研究部署不属于首条实现路径。

## 长期目标

我们希望让实验室能够用自己控制的基础设施，完成从实验开发、分发与参与，到数据收集、恢复和导出的完整流程，同时保留研究者对实验逻辑和科学判断的控制。

### 实验开发与平台接入分离

研究者使用熟悉的工具编写实验，通过独立的数据模块记录观测。需要连接平台时，加入 GEC 适配模块并替换少量配置，无需重写刺激呈现、随机化、计时和任务流程。先支持 Godot，再按真实需求验证 jsPsych、lab.js、PsychoJS 等网页工具；PsychoPy 原生接入单独评估，不预先承诺全部兼容。

### 两种发行方式，共用同一套数据服务

对于网页实验，研究者在 GEP 后台上传标准发行包，完成验证、预览和批准后获得参与链接。对于独立程序或较大的实验，研究者登记研究与版本，从后台导出连接配置，随程序通过适合的渠道发送给参与者；资源分发位置与收数服务器可以不同。

参与者不需要安装 GEP 服务器，也不需要填写服务器地址。网页与原生程序通过集成的 GEC 接入指定研究。研究者可选择无需 ID、发放 ID、发放 ID 与密码三种参与方式，平台使用研究内的稳定标识关联参与和数据。

### 面对网络与程序中断，数据状态仍然清楚

网页和原生实验先保存本地记录，再后台分批上传。断网时保留未确认数据，连接恢复后继续传输；服务器明确确认、去重，并在实验结束后核对记录是否收齐。

实验允许恢复且提供有效检查点时，从明确的试次或阶段边界继续；没有恢复规则时保留数据并报告限制。任务完成、本地保存、服务器收齐和科学上可用分别展示，不以一个“成功”状态代替全部事实。

### 研究者能够通过图形界面独立完成日常工作

后台覆盖研究与版本、参与入口、名单和权限、实验发布、采集状态、受控恢复及数据导出。日常使用不要求研究者操作数据库或服务器命令。输出保留字段含义、单位、版本和来源，平台不擅自修改评分、排除标准或分析规则。

### 可维护的自托管与公开开发

支持在经过验证的实验室局域网或 VPS 环境中部署，逐步完善安装说明、配置检查、备份恢复和维护交接。平台代码公开开发，能力与限制以实际测试结果为依据，便于审查、复现与协作。

这些是产品方向，不是当前已交付功能或对所有环境的保证。真实研究启用前，仍需针对具体实验完成隐私与同意、计时、数据治理、备份和使用验收。

## 开发进度

开发将连续推进真实数据链路、插件可靠性和研究者图形首版，以可复现的工程证据更新能力状态。具体研究的科学协议、计时要求和实际使用验收单独进行。

公开仓库将承载代码、测试、可公开说明及后续验证结果。内部设计材料和任务记录不随仓库分发；本 README 不依赖这些本地文件。
