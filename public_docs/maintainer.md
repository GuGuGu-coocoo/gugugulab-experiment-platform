# 维护者说明

仅在明确合成环境运行。[启动指南](quickstart.md)说明实例初始化与构建；不得重新初始化已有实例。管理站与实验资源维持信任边界，GEP_PUBLIC_API应包含实验服务实际协议、hostname和端口。旧session/下载/队列不因修改此配置自动迁移。

03A的GUI与附件修复无数据库迁移；03B为纯新增账号治理与预览迁移（PermissionPreview 表）。metadata下载保留no-store与下载时授权。权限UI不替代后端检查，Owner不可通过研究成员撤销操作降权。Owner 行在账号管理（生命周期操作、实例权限矩阵与批量导入）中始终只读，Owner 本人也不能对自己执行这些操作；Owner 修改自己的密码使用自助入口 /account/password，与账号管理操作分开。Owner/Admin/普通用户角色、账号重置、实例权限矩阵、有界XLSX用户/权限与名单导入和安全迁移演练工具已按03B实现，并通过服务端与真实Chrome工程检查（T26工程证据；人工T17仍待独立非开发者执行）。数据库变更为纯新增：旧账号默认普通用户，Owner仍由实例指针唯一决定，旧研究授权不会被自动改写或扩大，identity_mapping.read与session.view不自动补授。接管限制按（研究，权限）逐项比较：操作者必须在同一研究可行使且可委派目标账号的每项权限（含目标的不可委派权限），否则拒绝改密、停用与启用；Admin可管理其他Admin的账号生命周期，但任命/降级Admin与Owner行仅Owner可操作。所有权限写入（矩阵、冲突收敛、Excel导入与旧研究页兼容路由）都要求当前治理版本、可见性前置与预览绑定；预览绑定操作者、操作内容、输入摘要与目标状态，过期或被并发修改即整批拒绝，审计失败回滚，旧研究页只保留兼容入口并指向 /users。已消费预览的重放只有在操作者仍持有该操作当前授权（实例角色、研究范围、目标接管条件与强制改密状态）时才幂等返回结果，被撤权或角色变化后不再返回旧结果，也不会重复写入或审计；名单导入的私密暂存绑定完整规范化内容（含密码哈希）、研究模式与治理版本，只改暂存哈希同样整批拒绝。审计保存每个受影响动作的完整布尔状态（是否授予与是否可委派），不含秘密。XLSX 解析使用锁定版本的 openpyxl（MIT），并在展开前对原始工作表 XML 实施有界检查：2 MiB 压缩、10 MiB 展开、1000 行、32 列上限，拒绝稀疏远端单元格、超界声明维度、表头/其他工作表公式、宏与外部关系链接，正常模板与文本 001 仍通过。已消费预览在提交时清除暂存；过期未确认的私密暂存由 `core.permissions.purge_sensitive_staging` 有界清理，也可用 `.venv/bin/python tools/phase03_purge_previews.py --repeat` 对所选 GEP_DATA_DIR 执行。

目标组件检查：`.venv/bin/pytest -q tests/test_t17_foundation.py tests/test_gui_packages.py tests/test_http.py`。Windows x64 平台契约、构建门槛与冻结包检查：`.venv/bin/pytest -q tests/test_phase03_windows_build.py tests/test_phase03_windows_packages.py tests/test_phase03_packages.py tests/test_phase03_releases.py`，以及用固定本机 Godot 4.7.2 与官方 Windows 模板交叉导出的 `.venv/bin/python tools/phase03_verify_windows_package.py --verify`（隔离数据目录/数据库/端口，只做交叉构建与冻结包工程验证；导出与引擎声明子进程必须以真实退出码 0 通过，模板在复制前按官方固定 SHA-256 校验，`GEP_GODOT_TEMPLATES` 覆盖目录字节不符直接失败；它不执行 Windows 程序，Windows 实机执行始终记为 NOT_RUN，需真实 Windows 主机另行验收）。账号治理与迁移演练检查：`.venv/bin/pytest -q tests/test_phase03_accounts.py tests/test_phase03_migration.py`。实例权限矩阵与XLSX导入检查：`.venv/bin/pytest -q tests/test_phase03_permissions.py tests/test_phase03_excel.py`。隔离真实浏览器检查：`GEP_T17_BROWSER=1 .venv/bin/pytest -q tests/test_t17_browser.py`、`GEP_T17_BROWSER=1 .venv/bin/pytest -q tests/test_phase03_accounts_browser.py` 和 `GEP_T17_BROWSER=1 .venv/bin/pytest -q tests/test_phase03_permissions_browser.py`，需本机Chrome和Node依赖，仅启动pytest临时库和回环服务，不连接现有验收实例。浏览器工程检查不能代替独立T17。

迁移演练只允许在指定演练目录的新副本上进行：`.venv/bin/python tools/phase03_migration.py --verify --source <合成副本目录> --evidence-root <新演练目录>`。工具用SQLite备份接口只读复制源卷，私有复制instance/secret，只迁移副本，拒绝覆盖已存在目标，并在报告中给出迁移前后计数、引用摘要、矛盾授权与源文件哈希不变结论；禁止对真实验收卷直接执行migrate。

真实研究、VPS/DNS/TLS、独立备份恢复与科学验收仍需另行授权。发布不得包含内部开发文档、数据库、凭据、下载或恢复文件。
