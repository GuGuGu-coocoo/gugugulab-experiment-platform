# 独立研究者验收

这是 Phase 03 的 T17 验收：请一位未参与开发的人，使用合成数据独立完成研究者工作流。开发者准备环境和文件、观察并记录问题；遇到困难时先记录，再决定是否提供帮助。需要帮助才能完成的步骤不能直接标为独立通过。

## 开始前

- 维护者提供可访问的合成后台、单独的测试账号和测试包。密码单独交付，不放进 ZIP、截图或反馈表。
- 使用 Chrome。网页可在已测试的 Mac/Windows 环境操作；独立原生程序目前只实测 macOS arm64。
- 所有姓名、ID、密码和答案均使用虚构测试值。当前版本不用于真实研究。
- 预留约 30–45 分钟。无需安装 Godot、编写代码或手打命令。

## 按顺序操作

1. **登录并创建研究。**确认能找到自己创建的研究；另建一项研究，确认能切换且对象不混用。
2. **设置参与方式。**分别试用无需 ID、名单 ID、ID+密码。名单保留 `001` 的前导零；未知 ID/错误密码应拒绝，正确凭据可进入。已有批准发行后不能偷偷改变冻结政策，换研究测试另一模式。
3. **登记原生构建和导出配置。**将提供的 `native_descriptor.json` 内容复制进构建描述框，登记并批准，下载公开连接配置。配置里不应出现管理员密码或被试密码名单。若在受支持的 Mac 上测试原生程序，将配置命名为 `connection.json`，放在解压后的 `.app` 同级，再运行两试次。
4. **上传网页包。**选择 `web_experiment.zip`，观察上传和验证结果。先试一个明显错误的文件，应明确失败且能重试。有效包通过后，进入隔离预览；预览不会成为正式参与数据。
5. **批准和招募。**批准合成发行、打开招募，找到参与入口，完成两个左右键试次。无需安装 GEP 客户端。关闭招募后，新参与应被拒绝；已经准入的有效旧会话按上传窗口处理。
6. **查看收尾和导出。**找到刚才的会话及服务器收齐状态，创建 JSONL 固定快照并下载；再下载 CSV 和元数据。两种事件结构应可识别，CSV 保存 JSON 文本而不是自动展开科学变量。
7. **尝试受控恢复。**在新会话完成 Trial 1、看到 Trial 2 后保存恢复 JSON，再关闭窗口。研究者签发一次性恢复许可，在原设备/原浏览器输入会话 UUID 和许可，应从 Trial 2 恢复。已结束但待传的数据只恢复补传，不再进入试次。
8. **邀请和成员权限。**邀请一个虚构的新测试账号，只给必要权限。用独立浏览器配置登录该账号，核对只能访问被授权的研究和动作。撤销权限后，旧下载链接也应被拒绝；有限 Admin 不能给自己或他人增加未获委派的权限。

## 记录结果

每步填写：通过 / 失败 / 需要帮助 / 未运行。写下卡住的位置、预期和实际行为、浏览器版本及截图文件名；不要记录密码、一次性许可或真实个人信息。

只有独立完成且结果符合预期的步骤才算通过。遇到阻断问题，保留页面和未确认数据并通知维护者，不清浏览器存储、不重装、不重复开始来掩盖问题。

T17 完成后再判断 Phase 03 是否通过；它不批准正式研究、生产部署、科学计时、伦理或数据治理。
