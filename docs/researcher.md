# 研究者操作说明

仅供合成测试。参与模式与招募状态显示已保存值。名单每行一个ID，密码模式使用标准CSV两列：`001,"synthetic,password-long"`；密码至少12字符，含逗号用双引号包围。ID保留前导零，整批存在重复或错误时不导入；成功会显示新增数量，不显示密码。账号管理页还提供有界 XLSX 模板与导入：用户与权限模板（create/update/disable/enable，已有账号必须写明当前版本，导入永不重置或覆盖已有密码，create 默认发出一次性邀请）与名单模板（仅追加，已有 ID 永不覆盖；文本 `001` 原样保留，数字形式 ID 被拒绝，不会猜测前导零）；上限 2 MiB、展开 10 MiB、1000 行、32 列，公式、宏、外部关系链接、稀疏远端单元格与超界声明维度被整体拒绝，表头或其他工作表的公式同样拒绝，逐行错误不执行任何行。名单密码在预览时立即哈希到私密暂存，预览、会话、Cookie、日志与导出都不含明文或哈希；暂存绑定完整内容，提交成功后立即清除，过期未确认的暂存由有界清理路径移除。

招募选择后立即提交；暂停/关闭均拒绝新参与，已有有效会话仍按原窗口上传。已有批准发行后政策冻结，不能据此修改旧发行。原生发行不显示网页入口；登记了程序归档的原生构建在批准时生成平台完整包，可在发行列表下载并与 `connection.json` 一起分发（该配置已随包冻结，解包后直接启动，无需替换文件）；只登记描述、不提供程序归档的旧兼容路径仍不提供平台下载。macOS arm64 与 Windows x64 使用同一套流程：macOS 程序归档是整个 `.app`，Windows 程序归档是包含 EXE、PCK、原生依赖与 GDExtension 清单的程序根目录；Windows 描述必须显式声明程序根、入口、依赖与清单，服务端按声明的名字核对真实 PE x86-64 映像与 PCK 版本，不要求任何固定程序名。

公开门户与当前发行（03C 工程版，03D 起平台感知）：研究页可单独勾选“公开到参与门户”，并填写公开简介、预计时长与设备要求；公开只改变门户展示，不改变参与模式、名单或招募。必须显式选择“当前发行”，可以是本研究已批准且带已发布 Web 包的发行，也可以是已批准且带平台完整包的完整原生发行；只登记描述、没有程序包的原生发行不可选。切换只对新参与生效，旧会话、待上传、恢复、下载、配置与已发布包保持原发行。门户按平台呈现：Web 当前发行提供浏览器开始入口；完整原生当前发行显示独立程序（Windows x64 或 macOS arm64）参与说明，不生成 `/run/.../web/index.html` 路径，也不把受控的完整包下载变成门户公开下载——完整包仍只在持有 build 权限的账号内下载；原生完整包缺失或被篡改时门户失败关闭，不显示任何开始入口。过期研究发布版本提交会被拒绝且不写入，变更写入前后审计。公开门户只列出“公开 + 招募中 + 有效当前发行”的研究；私有不因开放招募而公开；已结束研究默认不显示，需显式勾选才显示无开始按钮的简介。稳定研究入口为 experiment origin 的 `/join/<study_id>`；点击“开始参与”会带着页面观察到的发行与发布版本经过平台入口校验，页面过期时显示“研究入口已更新”并要求刷新，不会加载旧版本应用或创建旧发行新会话；刷新后按新发行进入。旧直达 `/run/<release_id>/…` 不带该绑定时仍按原准入契约保留，不会重定向到新发行。

创建固定快照后可下载JSONL、CSV和metadata.json；元数据不包含records。撤权后旧链接仍拒绝；下载时重新授权。无权限操作不显示或说明原因，后端仍检查权限。表单拒绝显示错误，不代表保存成功。构建与发行页的上传失败会在原地显示具体原因（中英文一致：压缩包无效、程序摘要与描述不一致、描述字段或 schema 不合法、原生包缺少入口/依赖等），失败不产生新构建或发行，旧发行保持原状；批准合成发行成功后定位到同一研究“构建与发行”页的对应发行条目。

后台信息架构（03E 工程版）：登录后是卡片式“我的研究”首页，左侧为固定侧栏（当前账号、我的研究、研究模块、账号与权限、修改密码、退出登录）。研究被拆成独立模块页：默认研究地址是概览（保留旧直达链接与旧表单提交路径），另有序 `participation`（参与与名单）、`builds`（构建与发行）、`recruitment`（招募与门户）、`sessions`（会话与恢复）、`exports`（导出）。页首可用本地偏好切换 `语言（中文／English）` 与 `主题（跟随系统／亮色／暗色）`，偏好通过本站 Cookie 保存、不用第三方分析或外部资源，科研内容本身不随界面翻译改变；通用界面文案（侧栏、模块、表单控件、预览、一次性通知、错误提示与 XLSX 逐行错误）均提供中文／English，权限动作标签也随界面语言显示、动作代码不变。会话页按服务器时区显示时间并标注时区；支持按名单 ID 精确搜索（保留 `001` 前导零，只匹配完全相同文本）、按服务器状态筛选（未开始／进行中／已声明待收齐／服务器已收齐／已撤销，同一名单可有多次会话），并按创建时间与 ID 稳定分页；“服务器已收齐”只表示声明的记录已到达，不代表科学验收。名单查询（参与与名单页）支持精确 ID 搜索与分页；导出页列出固定快照并可下载 JSONL/CSV/metadata。会话状态、筛选与计数在数据库侧计算，只取当前页的会话记录，事件明细不会整表载入；账号权限页同样只加载当前页账号及其授权，并只加载该页授权涉及的研究，冲突列表按数据库计数分页，可配置研究选择支持按名称检索并在超限时显式提示。权限按服务端动作过滤：仅有 study.view 只能看到概览与数量；具体名单身份需要 identity_mapping.read；具体会话行需要 session.view；只有 session.recover 时可以按会话 UUID 签发六位恢复码，恢复权限不会带来原始数据导出或身份映射权限；缺少对应权限的查询与直接提交返回 403，不显示无权控件。

公开门户（03E 工程版）：门户列表改用稳定研究链接 `/join/<study_id>` 选择研究，不再在页面里暴露 release ID；只展示明确公开的简介、预计时长与设备要求，具体名单、会话、参与模式与管理入口都不出现。门户与稳定入口同样支持中文／English 与三种主题；私有不因招募公开而列出，未列出的私有研究其直达稳定入口仍按 03C 准入契约工作；暂停、结束、无当前发行等状态各自显示说明且不给开始按钮，旧会话继续绑定原发行。

账号权限页（/users）已实现实例权限矩阵：先勾选研究可见性，再展开显式动作；账号多时可按用户名搜索、分页查看，账号名列固定以便横向查看；矩阵只加载当前页账号及其授权，并只加载该页授权涉及的研究（Owner 治理全部研究，因此覆盖全部研究目录）；Owner 与 Admin 都可只读查看实例内全部账号的授权元数据，超出操作者可管理范围的条目、Admin 看到的 Owner 行以及自己的行均为只读；只读查看不授予研究数据、会话、名单身份或导出权限，伪造的预览或确认仍返回 403；取消可见性会同时清除子权限，服务端拒绝“不可见却保留子权限”的矛盾提交。授权按实例版本运行：新实例明确启用 v2（固定研究动作 study.view、study.configure、build.upload、build.preview、release.approve_pilot、recruitment.manage、data.export_raw、identity_mapping.read、session.view、session.recover、audit.view、study.delete，固定平台动作 study.create、accounts.view、accounts.create_user、accounts.manage_user、accounts.create_admin、accounts.manage_admin、accounts.delete_admin）；旧实例在 Owner 于 /users 用本人密码确认启用前继续按 v1 运行，启用只新增存储、不改写旧授权行。v2 下 user 默认仅有 study.create，Admin 默认有 study.create、accounts.view、accounts.create_user、accounts.manage_user，Owner 拥有全部能力；平台开关只能由 Owner 显式设置，且 Admin 不可被转授 accounts.create_admin、accounts.manage_admin、accounts.delete_admin（v2 本页已提供 Owner 专用平台开关界面：每个非 Owner 账号的七个开关只对 Owner 显示，与研究动作分开预览、分开提交，Admin 既看不到也提交不了）。v2 权限页一行一个账号（用户名旁标注 Owner／Admin／普通成员）：展开研究后显示该账号在此研究的最终有效勾选与来源文字（显式完整覆盖／角色默认或未来上界／显式授权／Owner 固定目录），不再显示“可委派”复选框；批量“全选/全不选”只作用于当前明确可编辑的范围并显示范围与变更数量，不包含筛选外研究、只读条目或未来权限；不可见研究只显示受限计数，不显示名称、数据或发行细节；未提交的勾选只保存在当前浏览器会话草稿中（不含密码），按当前账号与实例隔离，分页与筛选不会丢失；治理版本变化后草稿保留并标记为需重新核对，不会静默套用也不会整批丢弃。矩阵提交、平台开关与永久删除的密码确认与错误共用一个对话框（v1 页面保持原内联确认）：取消或 Escape 不发送任何请求并把焦点还给真实触发控件；提交在途时锁定按钮且锁独立于弹窗开关，Escape/关闭/重新打开都不能重复发送或解锁；网络结果未知时先查询只读的预览状态（只返回本人操作的最小状态，不含研究名、账号名或结果对象；尚未完成表示查询时未完成、原请求可能仍在途，按原预览重试不会重复写入；已执行表示重放不会重复写入），不显示未经服务器确认的成功。v2 的研究权限：Owner 为全目录；Admin 在无显式完整覆盖的研究上使用 Owner 设定的未来上界或固定模板，普通用户使用显式授权；没有 study.view 就没有任何研究权限。显式完整覆盖（包括空列表）优先于角色默认、未来上界与旧授权行：被 Owner 取消可见性的研究不会因角色默认或旧授权重新出现在首页、研究选择器或权限矩阵中，直接请求同样被拒绝。持有 study.create 的账号（含未来上界为空的受限 Admin）创建研究时会一次性获得该研究的全部业务动作，完整显式覆盖与授权行在同一事务写入，之后 Owner 撤权不会因创建者身份自动恢复；授权版本只接受精确的 1 或 2，未知或畸形版本的实例拒绝创建、列表与所有权限入口且不写入任何更改。v2 修改他人权限需要操作者具备目标角色的生命周期能力（普通账号 accounts.manage_user；Admin 目标 accounts.manage_admin，删除还需 accounts.delete_admin），并在该研究同时具备 study.view 与 study.configure，且不能授予自己不具备的动作；修改某一研究的差异不会改写目标在其他研究的授权（整账号接管比较前后全部研究与平台权限），自己与 Owner 行永远不可写，默认 Admin 不能管理其他 Admin。所有权限入口（权限页、导出、恢复、导入与迁移启用）调用同一套存储策略计算：请求里自造的 study_overrides、platform_overrides 或版本字段一律无效；v2 下旧 member.manage/permission.delegate 没有含义，旧研究成员邀请/撤员入口明确返回 409 并提示改用账号权限页，旧“可委派”标志不参与判断，v2 写入完整研究覆盖列表而不改旧授权行。新增显式动作 identity_mapping.read（查看具体名单身份与会话对应，不含答案）与 session.view；它们不会自动补授给任何已有账号，只能显式分配。所有矩阵、冲突收敛、平台开关与 Excel 导入都先预览、再用本人密码一次性确认：预览绑定操作者、操作内容、输入摘要与当前治理/目标版本，过期或任何相关变化都会整批拒绝且零部分写入；重复提交同一成功预览是幂等的，但会重新核对当前角色、研究范围、目标接管条件与强制改密状态，操作者被停用、降权、被撤销研究权限或目标权限提高后不再返回旧结果。Owner 由实例指针唯一决定，可任命或降级 Admin；v2 默认 Admin 不能管理其他 Admin（含改密、停用、启用），Owner 显式授予 accounts.manage_admin 后也只能在能支配目标全部研究权限且自己具备 view+configure 的研究内维护。新账号可通过邀请（本人设置密码，24 小时内一次性有效）或一次性临时密码创建；研究者密码统一为至少 6 位且至少各含一个 ASCII 大写字母、小写字母、数字与可见标点符号（空格不计作符号、不自动去除首尾空白，`Aa1!aa` 合格、`Aa1aaa` 不合格），服务器生成的临时密码随机且保证四类；弱密码会被拒绝并显示同一规则的中文或 English 具体说明，被拒绝的激活不会消费邀请，已有账号的密码哈希保持不变；邀请创建后页面只显示一条由受控管理主机名与服务器实际端口组成的完整设密链接（显式配置的管理来源优先；未配置时不采用请求头中的端口、也不读取转发的来源），被邀请人打开链接自行设置密码；临时密码账号不使用该链接，直接用用户名与临时密码登录并在首次登录后修改密码。临时密码首次登录必须改密，改密、重置或停用会使旧登录会话失效。已有账号的密码哈希不会被重置，仅在下一次本人设置或管理员重置时按当前规则校验。账号治理操作需重新输入操作者密码、校验并发治理版本并写入脱敏前后审计，一次性密钥只显示一次、不进入审计或导出。权限审计在 v2 保存前后完整策略快照，v1 仍按动作保存“是否授予 / 是否可委派”的完整布尔差异。缺少 study.view 的旧授权子权限被视为矛盾：不自动扩大可见性，由 Owner 在预览后显式选择补 view 或移除冲突子权限；接口、浏览器页会拒绝并提示。矛盾列表按数据库计数分页（预览与确认仍覆盖全部矛盾）；名单模板的研究选择按名称检索并限量展示，超限时明确提示，不静默截断选择。旧实例的 v1→v2
