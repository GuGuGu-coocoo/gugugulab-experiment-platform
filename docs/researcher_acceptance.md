# 研究者人工测试（T17）

使用合成数据检查研究者与参与者工作流。记录实际操作人是否参与设计／开发，以及每项是否需要帮助；受指导的结果不能写成独立通过。不强制“设计者先测试，再交给非开发者”的顺序。

2026-10-20，项目设计者完成本轮体验后确认“所有测试都通过了”，同意冻结 0.1.0。这是人的整体确认，不是一次新增的非开发者独立验收，也不补写未观察到的逐项或原生实机结果。[当前结果及历史工程证据](verification.md)。下表是后续测试的空白记录模板，不代表 0.1.0 尚无人测试。

## 开始前

维护者准备可访问的合成实例、单独的测试账号与本轮文件，不重建现有实例。账号密码不放进测试包或截图；只用合成 ID 和数据。

使用 Chrome；原生程序须从本次实例内发布并下载，不能混用旧实例的连接配置。当前恢复入口暂不公开，不将恢复操作列为本版本常规界面必测项；保留已有队列和待传数据。

## 操作范围

1. **登录与研究。**登录后台，创建合成研究，分别检查无需 ID、ID、ID 与密码三种参与方式；名单使用模板导入，并核对已有 ID 及参与次数。临时密码账号首次登录应要求改密。
2. **实验上传与发布。**上传本轮 Web 包，观察验证和隔离预览；坏包应就地报错且不改变旧版本。发布测试版本，选择当前版本并打开招募，核对门户与分享入口。原生测试则登记或上传对应平台程序，并下载该实例生成的完整包。
3. **参与与结束。**从参与入口开始实验，完成任务，检查结束语和完成状态。本地保存、上传等待与服务器确认应能区分；有条件时记录断网本地保存、复网补传，保留故障现场。
4. **状态与导出。**在参与记录中搜索 ID、筛选完成状态，创建固定快照，实际下载并打开 JSONL、CSV 与 metadata，核对记录和合成 ID。需要身份映射权限的操作不能被其他账号访问。
5. **账号与权限。**以虚构账号测试邀请／临时密码、权限勾选、提交和本人密码确认。验证研究不可见时其他权限关闭，受限 Admin 不能越权或修改 Owner。撤销权限后旧链接的新请求应被拒绝。
6. **停用与删除。**仅用本轮可丢弃的合成账号和研究，先检查后果提示，再测试停用／启用或永久删除；有数据的研究应先确认导出已保存。其他研究和账号不应受影响。
7. **界面体验。**查看中英文、主题、窄屏和键盘操作；权限展开不应挤乱列宽，按钮应明确显示展开／收起与提交结果。记录难懂术语、找不到的入口和错误提示。

遇到问题先记录，阻断问题交维护者诊断；不清浏览器存储、不删除未确认数据、不靠重复开始掩盖失败。操作说明见[研究者指南](researcher.md)。
