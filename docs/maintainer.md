# 维护者说明

仅在明确合成环境运行。[启动指南](quickstart.md)说明实例初始化与构建；不得重新初始化已有实例。管理站与实验资源维持信任边界，GEP_PUBLIC_API应包含实验服务实际协议、hostname和端口。旧session/下载/队列不因修改此配置自动迁移。

03A的GUI与附件修复无数据库迁移；03B为纯新增账号治理与预览迁移（PermissionPreview 表）。metadata下载保留no-store与下载时授权。权限UI不替代后端检查，Owner不可通过研究成员撤销操作降权。Owner 行在账号管理（生命周期操作、实例权限矩阵与批量导入）中始终只读，Owner 本人也不能对自己执行这些操作；Owner 修改自己的密码使用自助入口 /account/password，与账号管理操作分开。Owner/Admin/普通用户角色、账号重置、实例权限矩阵、有界XLSX用户/权限与名单导入和安全迁移演练工具已按03B实现，并通过服务端与真实Chrome工程检查（T26工程证据；人工测试在修复回归后安排，T17编号保留、帮助/失败/未运行如实记录）。数据库变更为纯新增：旧账号默认普通用户，Owner仍由实例指针唯一决定，旧研究授权不会被自动改写或扩大，identity_mapping.read与session.view不自动补授。接管限制按（研究，权限）逐项比较：操作者必须在同一研究可行使且可委派目标账号的每项权限（含目标的不可委派权限），否则拒绝改密、停用与启用；Admin可管理其他Admin的账号生命周期，但任命/降级Admin与Owner行仅Owner可操作。所有权限写入（矩阵、冲突收敛、Excel导入与旧研究页兼容路由）都要求当前治理版本、可见性前置与预览绑定；预览绑定操作者、操作内容、输入摘要与目标状态，过期或被并发修改即整批拒绝，审计失败回滚，旧研究页只保留兼容入口并指向 /users。已消费预览的重放只有在操作者仍持有该操作当前授权（实例角色、研究范围、目标接管条件与强制改密状态）时才幂等返回结果，被撤权或角色变化后不再返回旧结果，也不会重复写入或审计；名单导入的私密暂存绑定完整规范化内容（含密码哈希）、研究模式与治理版本，只改暂存哈希同样整批拒绝。审计保存每个受影响动作的完整布尔状态（是否授予与是否可委派），不含秘密。XLSX 解析使用锁定版本的 openpyxl（MIT），并在展开前对原始工作表 XML 实施有界检查：2 MiB 压缩、10 MiB 展开、1000 行、32 列上限，拒绝稀疏远端单元格、超界声明维度、表头/其他工作表公式、宏与外部关系链接，正常模板与文本 001 仍通过。已消费预览在提交时清除暂存；过期未确认的私密暂存由 `core.permissions.purge_sensitive_staging` 有界清理，也可用 `.venv/bin/python tools/phase03_purge_previews.py --repeat` 对所选 GEP_DATA_DIR 执行。
